# 사이드바 폴더 펼침 설정

펼침 상태 소유자는 기존 `useFolders`이며 FolderTree는 전달받은 상태와 콜백으로 마우스/키보드 렌더링만 수행한다. 원고와 분리된 UI 설정을 `localStorage['seam-note:expanded-folders:v1']`에 펼쳐진 폴더 ID 배열로 저장한다.

- 최초 lazy initializer에서 읽는다. 누락/손상/접근 실패는 null, 유효한 `[]`는 모두 접힘이다.
- 설정이 없을 때만 현재 선택 원고의 조상 폴더를 기본으로 펼친다. 자동 기본값 자체는 저장하지 않는다.
- 사용자의 펼침/접힘은 전체 현재 상태를 확정한다. React effect에서 저장하며 렌더링/상태 updater 안에서 쓰지 않는다.
- 저장된 설정이 있으면 URL 이동/직접 진입/뒤로가기로 조상을 자동으로 열지 않는다. 에디터의 원고 선택과 사이드바 접힘은 독립적이다.
- 명시적인 생성은 생성 위치를 보여주기 위해 해당 경로를 펼치고 저장한다. 다른 폴더 상태는 보존한다.
- 삭제/미표시 ID는 트리 렌더링에 영향이 없다. 부분 Workspace/오프라인 snapshot만 보고 설정을 제거하지 않는다. 새 폴더 ID는 자동으로 기존 설정에 포함되지 않는다.
- 저장 접근/쓰기 오류는 무시하고 현재 세션 React 상태로 계속 동작한다. 차단 환경에서는 재실행 복원을 보장할 수 없다.
- 같은 브라우저 프로필·origin에서 유지한다. 5173/4173, localhost/127.0.0.1은 서로 다른 저장소다. 탭 간 실시간 설정 동기화는 이번 범위가 아니다.

서버 API, 원고/Draft/Outbox, IndexedDB v1~v4, PWA SW에는 변경이 없다.

## 폴더/원고 수동 서버 저장 확인

펼침 기능과 별개인 기존 생성 계약이다. 온라인에서도 `+`로 생성하면 우선 로컬에만 기록된다.

1. 합성 테스트 이름으로 최상위 폴더 A와 하위 B를 생성한다. Sidebar `로컬` 표시를 확인한다.
2. B를 선택한다. 사이드바의 `폴더 서버에 저장`을 누르면 `syncLocalFolder`가 A→B 순서로 필요한 미확정 부모와 B를 POST한다. 문서가 없어도 가능하다.
3. 또는 B에 새 노트 C를 만들고 편집한 뒤 에디터의 `서버에 저장`을 누른다. `syncLocalNote`가 A→B→C를 생성하고, 전송 도중 추가 입력이 있으면 기존 `syncOneNote`의 후속 PUT/ACK 경로를 사용한다.
4. DevTools Network에서 `/api/folders` POST와 `/api/notes` POST, 필요한 `/api/notes/{id}` PUT을 확인한다. 각 요청의 Idempotency-Key는 기존 operationId다. 응답 검증/로컬 ACK가 끝나야 `로컬` 표시가 해제된다.
5. `/api/workspace/tree` GET에서 해당 UUID를 확인한다. 다른 프로필에서 서버 목록을 조회하면 로컬 캐시와 구분해 확인할 수 있다.
6. 형제 폴더/다른 노트/폴더 아래 모든 노트를 일괄 저장하지 않는다. 폴더만 저장해도 하위 노트들은 별도로 저장해야 한다.
7. 실패 시 오류 문구와 Outbox pending/inFlight/conflict를 확인한다. 성공으로 표시되지 않으며 로컬 원고/작업은 보존한다. 온라인 복귀만으로 자동 전송하지 않는다.

선택된 폴더가 없거나 이미 서버 반영된 폴더에는 새 폴더 저장 버튼이 없다. 오프라인에서는 비활성화된다. 접힘과 선택은 별개이므로 폴더를 클릭해 접어도 선택된 폴더의 저장 버튼은 표시될 수 있다. 기존 데이터는 검증을 위해 임의 변경하지 않는다.
