# Offline-first 자동 동기화

## Git 기준과 범위

- main을 origin/main과 fast-forward 확인한 뒤 `1dce669`에서 `feat/auto-sync`를 생성했다. 시작 작업 트리는 깨끗했다.
- 기존 Tiptap·로컬 Draft·Outbox·CreationOutbox·expectedVersion·ledger·ACK·PWA를 유지한다. backend/Flyway/IndexedDB schema 변경 없음. 신규 dependency 없음.
- 현재 main의 배포 설정이나 Vercel 서비스를 임의 변경하지 않았다. 테스트는 합성 원고와 별도 PostgreSQL25521/API18821/production origin25203을 사용했다. 기존 개발 서버/DB/profile 변경 없음.

## 변경 순서와 파일

1. `autoSyncScheduler.ts`: 단일 timer/실행 gate, 이벤트 합치기, 입력 quiet/debounce, bounded retry/cooldown을 추가했다.
2. `useWorkspaceSync.ts`: 초기화/복구·local flush·서버 GET·기존 syncWorkspace 호출을 묶었다. 수동/자동이 같은 scheduler를 사용한다. Dexie 큐의 operationId 변화만 commit 신호로 사용하고 ACK/status-only 변화로 루프를 만들지 않는다.
3. `AppLayout.tsx`: 별도 생성 자동 hook 호출을 제거하고 URL의 selectedNoteId를 통합 hook에 전달했다. 로컬 본문이 있을 때 background GET의 로딩 문구가 편집기 레이아웃을 바꾸지 않는다.
4. `AppHeader.tsx`/`SyncStatus.tsx`: 기존 로컬 badge와 별개로 작은 서버 상태를 표시한다. 수동 버튼/단축키는 유지한다.
5. `workspaceCache.ts`: 첫 조회 전 로컬 schema/Draft/queue 초기화 barrier를 한 번 수행한다. 실패 시 초기화 promise는 다시 시도 가능하게 한다.
6. `noteQueries.ts`/`workspaceQueries.ts`: 선택 노트는 로컬 read 후 staleTime0 GET. 자체 focus/reconnect 재조회를 끄고 scheduler로 통합했다. 비방문 본문 전체 GET 없음.
7. `SyncCoordinator.ts`: 전송 코드는 유지하고 issue에 HTTP status를 추가해401/403을 구분한다.408/429는 bounded network retry로 분류한다. `client.ts`에는 모든 요청15초 timeout을 설정했다.
8. `package.json`: `typecheck: tsc -b` 추가. 기존 테스트의 저장소 mock에 initialize 경계를 추가했다.
9. `autoSyncScheduler.test.mjs`16개 및 `offlineWorkspace.test.mjs` 초기화 barrier1개를 추가했다. browser/autoSyncLive.cjs를 신규 작성했다. 기존 SIGKILL harness는 report env만 지정해 재사용했다.

## 정책

- 로컬 자동 저장400ms와 분리해 마지막 로컬 commit 후4초 quiet일 때 서버 실행한다. startup/focus/online/selection은150ms로 합치고 자동 시작 간격을3초 이상 둔다. 수동은 즉시 예약한다.
- focus/online/manual이 합쳐진 run은 실제 최신 GET을 강제한다. startup/selection만이면2초 이내 중복 조회를 재사용한다.
- 네트워크0/5xx/408/429는5/15/30초3회 retry(최초 포함4회), 소진 뒤 timer 없음. 새 실제 이벤트는60초 cooldown 뒤 재개하거나 수동/online으로 즉시 재개한다.
-401/403은 halt, 기타 영구 실패 operation은 현재 mounted scheduler의 자동 전송에서 제외한다. 수동 요청이 제외를 해제한다. 충돌/로컬 CAS/ACK 실패는 기존 규칙으로 보존하며 다른 독립 작업은 계속한다.
- Query 취소는 노트 전환에 따른 정상 취소로 처리하고 영구 오류로 자동 실행을 halt하지 않는다.

## 실제 결과

- `pnpm lint`, `pnpm typecheck`, `pnpm build`, Node202개 통과(기존185+신규17).
- 실제 Spring/PostgreSQL/production Chrome/PWA 기본18그룹 + offline hierarchy1 + rich text1 + 수동고아상태1 + 모바일1 =22개 통합 그룹 통과.
- 초기fill1회+insertText35회 → PUT1회, editor DOM/커서 유지. focus/visibility40개 burst → 선택 본문 GET1회.
- 지속503: 최초 포함 PUT4회로 정지, 모두 동일 key/hash. 실측 요청 시작 간격5069/15063/30078ms. 입력 이벤트와 무관한 반복 PUT 없음.
- 오프라인 hierarchy: 폴더 POST2→노트 POST1→추가 입력 UPDATE1, 최종 version1.
- 실제 Chrome SIGKILL 기존4조건 통과: 원래 키/payload 재시도, ACK rollback, 인위적 후속 작업 부재 복구, ledgerA/B각1, 최종 server version4. 후속 B 부재는 명시적 fault injection이지 새로 발견한 자연 발생 사고가 아니다.
- Native OS IME 후보창/Safari/전원 차단/storage eviction은 이번에 검증하지 않았다. 성능 p95나 개선률을 주장하지 않는다.

## 발견한 문제와 수정

- 초기 TS erasableSyntaxOnly·navigator narrowing build 오류 수정.
- 새 초기화 경계를 Node mock에 추가해 기존 query/cache 테스트2건 실패를 해결했다.
- 실제 PWA 첫 방문 controller 대기 harness는 clientsClaim=false 정책에 맞춰 테스트에서만 명시적 reload한다.
- 실제 focus가 startup에 합쳐지며2초 cache를 재사용해 서버 최신값을 누락하던 버그를 확인했다. needsFreshPull 정책/회귀 테스트로 수정했다.
- 노트 선택으로 취소된 Query를 영구 실패로 halt할 위험은 코드 분석에서 식별하고 정상 취소 처리했다. 강화된 A-B-A+자동 ACK 시나리오를 통과했다.
- 오프라인 생성 테스트에서 ‘새 문서’ 메뉴/플로팅 버튼의 중복 label 때문에 strict locator가 실패했다. 열린 details 메뉴로 범위를 제한해 다시 검증했다. 제품 생성 로직을 우회하지 않았다.

## 최종 보완 검증

- 수동 DevTools 조작으로 Outbox만 사라진 Dirty Draft는 전송 완료로 오인하지 않도록 추가 검사했다. inactive body GET/PUT0, 원본 Draft 유지, 확인 안내를 실제 Chrome에서 검증했다. 자연 발생 버그로 주장하지 않는다.
-390×844 모바일에서 자동 ACK, 가로 넘침 없음, Drawer 노트 선택/URL 동작을 확인했다. 새 서버 상태 문구는 wrap해 기존 버튼을 밀어내지 않는다.
- 정상 Web Lock 경합은 네트워크 실패 경고 대신 대기 상태로 표시한다. data/ACK 경계는 동일하다.
-401/400/503/응답유실은 테스트 프록시 fault injection이고, 정상 저장/409/404/ledger는 실제 Spring/PostgreSQL이다. 인증 서버/실제 OAuth를 검증했다고 주장하지 않는다.
- 전체22 browser그룹 + SIGKILL4조건,202 Node tests 결과 요약은 docs/verification/2026-10-29-auto-sync-summary.json이다. 테스트 외 기존 DB에 요청을 보내거나 기존 사용자 프로필을 초기화하지 않았다.

- 브라우저 수동 재현용 `AUTO_SERVE_ONLY=1` production UI 프록시를 실제 실행하여 app/API HTTP200을 확인했다. 별도 Playwright 없이 사용할 수 있으며 실행 절차는 설계 문서에 기록했다. 검증 후 이번 작업의 격리 서버만 종료했다.
