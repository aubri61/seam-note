# 문서·폴더 편집 UI

## 구현

- 편집기 오른쪽 아래의 `새 문서` 또는 사이드바 `폴더` 옆 `+` → `새 문서`를 누르면 `crypto.randomUUID()`로 새 ID를 생성합니다.
- 새 문서의 제목과 본문은 빈 문자열입니다. 제목에 `제목을 입력해주세요`가 회색으로 표시되고 제목 입력으로 포커스가 이동합니다.
- 생성 위치는 사이드바 선택이 우선입니다. 폴더 선택 시 그 폴더 안에, 문서 선택 시 그 문서와 같은 상위 폴더에 생성합니다. 유효한 선택이 없으면 현재 편집 문서의 위치를 사용합니다.
- 선택한 문서를 다른 폴더로 옮기면 다음 생성 위치가 새 위치를 따릅니다. 헤더 경로는 현재 편집 중인 문서 위치를 보여줍니다.
- `+` → `새 폴더`는 선택 기준 위치에 새 폴더를 만들고 해당 폴더를 선택한 뒤 인라인 이름 입력으로 포커스를 옮깁니다. 폴더를 선택해도 오른쪽 편집 문서는 유지합니다. Enter로 확정하고 Escape로 취소합니다. 기존 항목은 트리의 F2로 이름을 변경할 수 있습니다.
- 노트를 클릭하거나 키보드로 선택한 후 Enter를 누르면 해당 문서를 편집합니다. 모바일에서는 Drawer를 닫고 제목으로 포커스를 옮깁니다.
- 제목과 본문 입력은 React 상태에 즉시 반영됩니다. 다른 문서나 반응형 레이아웃으로 전환해도 입력은 유지됩니다.
- 검색 입력의 전체 테두리가 hover/focus 시 둥글게 표시됩니다. 문서 제목과 본문으로 검색하며, 일치하는 문서의 상위 폴더를 함께 보여줍니다. 결과가 없으면 안내합니다.
- 트리에서 폴더와 문서를 드래그해 순서를 바꾸거나 다른 폴더로 이동할 수 있습니다. 최상위 이동도 지원하며 문서 안으로 드롭하거나 폴더를 자기 자신/하위 폴더로 옮기는 것은 막습니다.
- 검색 중에는 이동 대상과 순서가 모호해지는 것을 막기 위해 드래그를 비활성화합니다.

## 라이브러리 선택

[React Arborist](https://github.com/jameskerr/react-arborist)를 사용했습니다. 라이브러리의 트리 정렬·가상 목록·검색·선택·키보드 탐색을 활용하고 행 스타일은 기존 Emotion 테마로 구현했습니다. `react-dnd`, `react-dnd-html5-backend`는 공식 필수 peer 의존성입니다. UUID나 테스트를 위한 패키지는 추가하지 않았습니다.

현재 드래그는 HTML5 마우스/트랙패드 방식입니다. 터치 제스처를 위한 별도 DnD backend는 추가하지 않았습니다. 모바일의 폴더 열기, 노트 선택, 생성, 검색, 편집은 사용할 수 있습니다. 가상 목록의 폴더 펼침 배치는 Arborist가 처리하며 이전 CSS Grid 방식의 높이 전환과는 다릅니다.

## 상태와 저장 범위

`useFolders`가 문서 목록, 사이드바 선택 ID(selectedId), 편집 중인 문서 ID(activeId), 검색어, 폴더 펼침 상태를 관리합니다. 새 폴더와 새 문서는 모두 selectedId를 갱신하며 문서를 생성할 때만 activeId도 갱신합니다. `folderModel`은 UI와 독립된 트리 구성·경로·이동 함수를 제공합니다. `FolderTree`는 controlled data를 사용하고 생성·이름 변경·이동 결과를 상위 상태에 반영합니다.

현재 변경은 메모리에만 있으며 새로고침하면 초기화됩니다. 서버 API, 영구 저장, 자동 저장, 실제 동기화는 구현하지 않았습니다. 서식 버튼도 기존처럼 미연결 상태입니다. `로컬 저장 중` 배지는 기존 상태 UI이며 디스크 저장 완료를 의미하지 않습니다.

## 검증

- `pnpm test`: Node 기본 테스트 러너로 13개 테스트 통과. 현재 문서의 생성 위치, 같은 폴더 내 드롭 인덱스 보정, 폴더 간 이동 후 내용·경로 유지, 하위 항목 유지, 자기 자신·자손 이동 방지, 문서 안 드롭 거부, 최상위 이동과 제목 없는 문서·본문 검색을 검증합니다.
- `pnpm build`: TypeScript 및 Vite 빌드 통과.
- `pnpm lint`: 통과.
- 실제 브라우저: 새 문서 UUID·빈 제목·빈 본문·제목 포커스, 제목과 본문 입력, 노트 전환 후 입력 유지, 본문 검색, 새 폴더 이름 입력, 실제 마우스 드래그로 Work 폴더 이동, 이동한 문서 위치에 새 문서 생성, 반응형 전환 후 입력 유지, 모바일 선택·생성 시 Drawer 닫힘과 제목 포커스를 확인했습니다.

이전 `REFACTOR_VALIDATION.md`는 정적 UI 리팩터링 당시의 검증 기록이며, 이후 추가된 현재 기능의 범위는 이 문서를 기준으로 합니다.

## 입력·드래그 피드백 보완

- 새 문서 제목 포커스 요청은 트리의 생성 완료 처리와 분리해 트리에서 생성 요청을 소비해도 사라지지 않습니다. Drawer 안에서 생성하면 종료 후에도 제목으로 포커스가 복원됩니다.
- 제목·본문 입력에는 focus/focus-visible 외곽 outline을 표시하지 않습니다. 다른 버튼과 탐색 요소의 키보드 포커스 표시는 유지합니다.
- 우하단 생성 버튼은 56px 원형, 24px 연필 아이콘만 표시하며 접근 가능한 이름은 `새 문서`입니다.
- 유효한 드롭 대상인 닫힌 폴더 위에서 200ms 머물면 자동으로 펼칩니다. 이탈·드래그 종료 시 예약된 펼침을 취소합니다. 드롭이 완료된 대상 폴더도 펼침 상태로 유지됩니다.
- Arborist 기본 파란 삽입선 대신 `theme.colors.border`를 사용하는 커스텀 Cursor를 렌더링합니다.
- 브라우저에서 버튼·메뉴 생성 후 제목 포커스, 입력 outline 없음, 원형 버튼 치수, 닫힌 Work 폴더로 실제 드래그 후 펼침과 경로 변경, 모바일 생성 후 제목 포커스를 확인했습니다.

## 선택과 생성 기준 검증

오른쪽에 My notes의 기존 문서를 연 상태에서 Work를 선택하고 `새 폴더`를 만들면 Work 아래에서 새 폴더가 강조되고 이름 입력에 포커스가 갑니다. 이 폴더를 `집필`로 명명한 뒤 다시 새 폴더를 만들면 `집필` 아래에 생성됩니다. 그 하위 폴더 `자료`가 선택된 상태로 새 문서를 만들면 `Work / 집필 / 자료` 아래에 문서가 생성되고 트리에서도 선택됩니다. 이 연속 동작과 새 문서 제목 포커스를 실제 브라우저에서 검증했습니다.

## 폴더 도메인 명명과 이동 후 선택

- 폴더/문서 트리의 상태와 모델은 `features/folders`의 `useFolders`, `folderModel`, `FolderItem`, `FolderTreeNode`, `FolderTree`를 사용합니다. 테스트는 `tests/folderModel.test.mjs`입니다.
- 실제 워크스페이스 선택 UI는 별도 `features/workspaces/WorkspacePicker.tsx`입니다. 폴더 트리와 워크스페이스를 같은 도메인으로 취급하지 않습니다. DB 스키마나 API는 이번 작업에서 추가하지 않았습니다.
- 드래그는 클릭 선택을 자동으로 수행하지 않습니다. 성공한 이동에서 `selectedId`를 이동한 항목으로 갱신하고 목적지 조상을 펼친 뒤, Arborist의 표시 목록이 갱신된 다음 프레임에 선택과 행 포커스를 복원합니다. 생성/이동 처리 중 라이브러리의 이전 선택 콜백이 상태를 덮어쓰지 않도록 합니다.
- 이동은 현재 편집 문서(`activeId`)를 바꾸지 않습니다. 이동 후 다른 폴더를 직접 선택하면 그 새 선택이 다음 생성 위치로 우선합니다.
- 브라우저 회귀: 이전 폴더 선택 → 다른 문서를 닫힌 외부 폴더로 드래그 → 이동한 행 선택 → 새 문서가 목적지 폴더에 생성되는 것을 확인했습니다. 명시적으로 Journal을 다시 선택한 후 생성하면 Journal 아래에 생성되는 것도 확인했습니다.

원인과 상세 검증: [트러블슈팅](../docs/troubleshooting/2026-10-25-frontend-folder-move-selection.md).
