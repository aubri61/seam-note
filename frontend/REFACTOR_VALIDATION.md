# AppLayout / Sidebar 리팩터링 검증

검증일: 2026-10-25 (Asia/Seoul)

기존 테스트 스크립트·테스트 파일·테스트 러너가 없는 프로젝트이므로 새 테스트 프레임워크를 설치하지 않았습니다. 아래 결과는 로컬 Vite 앱의 실제 브라우저 조작, DOM/접근성 상태, 계산된 스타일로 확인했습니다.

## 재검증 절차

1. `frontend`에서 `pnpm dev`를 실행하고 데스크톱 너비로 새로고침합니다. 사이드바가 닫혔는지 확인합니다.
2. 토글로 사이드바를 열고 Work 폴더를 펼칩니다. 접고 펼칠 때 200ms 전환을 확인합니다.
3. 1100px 이하로 줄입니다. 사이드바와 Overlay가 남지 않고 에디터가 계속 보이는지 확인합니다.
4. 토글로 Drawer를 엽니다. 닫기 버튼으로 포커스가 이동하고 배경을 조작할 수 없는지 확인합니다.
5. Shift+Tab과 Tab으로 양 끝 포커스가 Drawer 내부에서 순환하는지 확인합니다.
6. Escape, 바깥 Overlay 클릭, 내부 닫기 버튼을 각각 사용합니다. 슬라이드 아웃 후 토글로 포커스가 돌아와야 합니다.
7. Drawer를 다시 열고 Work 폴더 상태를 확인합니다. 열린 상태로 1100px 초과로 넓힙니다. Drawer는 닫히고 자동으로 고정 사이드바가 열리지 않아야 합니다.
8. 데스크톱 토글을 누르고 Work 펼침 상태가 보존됐는지 확인합니다.
9. 에디터 제목에 포커스를 놓고 화면 크기를 바꿉니다. 제목 포커스와 정적 저장 상태가 유지돼야 합니다.
10. 동작 줄이기 환경에서는 전환 없이 열리고 닫히는지 추가로 확인할 수 있습니다.

## 범위와 남은 검증

- 노트 선택, 검색, 편집 및 저장·동기화의 실제 상태 검증은 해당 기능 구현 후 필요합니다.
- 읽기 전용 검색 입력에는 현재 보존할 입력값 상태가 없습니다. 폴더 상태는 AppLayout에서 제어합니다.
- Drawer 내부 워크스페이스 팝업은 임시 UI라 재마운트 시 닫힙니다.
- 에디터는 반응형 분기 바깥에 있으므로 반응형 모드가 바뀌어도 컴포넌트 타입·위치·key를 바꾸지 않습니다.
- 검증은 Codex 내장 브라우저에서 수행했습니다. 별도 크로스 브라우저·스크린 리더·OS reduced-motion 검증은 수행하지 않았습니다.
